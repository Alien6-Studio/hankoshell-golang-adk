# 0.7.2 — Application secret rotation

## Product outcome

Product dashboards rotate the secret of their own confidential applications through the Hanko API, without opening the Hanko console. `NewApplicationSecretClient` (TypeScript: `HankoApplicationSecretClient`) is bound to one realm and an allowlist of client IDs. It reads application metadata without a secret and returns a new secret once on rotation; the previous secret stops working.

Go and TypeScript ship the same client and the same shared contract fixture. Existing clients and their contracts are unchanged.

## Authority

The platform route still requires realm administration. Keep the credential on the backend, restrict the dashboard action to operators and never log the returned value. A narrower delegated scope for named applications is a platform change outside this release.

## Qualification and delivery

The shared contract covers the request path, method, bearer and response mapping. Tests also cover the allowlist, unsafe identifiers, refusals without provider detail, mismatched or incomplete responses and a fresh credential per call. The signed tag and the protected release workflow publish the package.
